# 2026-08-06

## Latest Codex Desktop and three-platform support

Agent: Codex
Project root: `D:\Users\g-tty\Documents\ChatGPT\codex-web`

### Intent

Upgrade the fork to the latest official Codex Desktop renderer and provide a
maintainable macOS, Linux, and Windows setup path without losing the fixes that
landed on `0xcaff/main` after the two reference forks diverged.

### Baseline and discoveries

- Work started from clean `G-TTYg/codex-web` commit `8cc728d` on new branch
  `codex/latest-desktop-cross-platform`.
- `G-TTYg/main` and `0xcaff/main` are identical at the baseline.
- `Yiruma96/main` diverged at `8eaa937`: it contains seven Windows-focused
  commits, while current `0xcaff/main` contains fourteen different commits.
  Windows support must therefore be ported by behavior, not by replacing or
  merging the whole tree blindly.
- Official macOS appcast latest on 2026-08-06 is `26.730.61639` (published
  2026-08-05).
- The locally installed Microsoft Store package is `OpenAI.Codex
26.730.8199.0`. Its extracted ASAR and Electron versions still need to be
  recorded independently.
- The baseline only documents macOS/Linux and pins Desktop `26.707.30751`.
- No repository-local agent/project contract existed before this work.

### Plan

1. Preserve current `0xcaff/main` runtime fixes and characterize the latest
   macOS and Windows Desktop bundles.
2. Port the Windows ASAR extraction, fail-closed semantic patching, and native
   launch flow from `Yiruma96/main`, updating it for the latest bundle.
3. Upgrade the Unix source bundle and regenerate or repair patches against the
   latest official appcast release.
4. Unify package commands, version reporting, documentation, and generated-file
   exclusions across macOS, Linux, and Windows.
5. Verify the Windows build locally, run shared type/build checks, validate the
   Unix preparation path, and commit the completed slice locally.

### Affected boundaries

- Platform build adapters and official bundle discovery under `scripts/`.
- Unix unified patches under `patches/` and Windows semantic transforms.
- Shared renderer IPC shim and server shell shim only where the current
  Desktop protocol requires it.
- Package scripts, compatibility documentation, and generated-file rules.

### Verification target

- Exact version/brand/Electron metadata checks for each extracted bundle.
- Fail-closed patch checks with no skipped transforms.
- `npm run build:browser` and `npm run build:server` on the Windows bundle.
- Shared type/build checks and Unix bundle preparation using the official
  macOS release, runnable from both macOS and Linux.
- Runtime smoke check on Windows if the installed CLI and bundle can start.

### Risks / TODO

- A browser build proves patch compatibility but not every interactive Desktop
  flow. New/existing task, prompt prefill, file picker, and reconnect behavior
  need smoke coverage.
- macOS and Linux runtime behavior cannot be fully exercised on this Windows
  host; their official bundle extraction and deterministic build path can still
  be verified here where tooling permits.

### Completed outcome

- Windows Appx `26.730.8199.0` contains ChatGPT-branded ASAR `26.730.61639`
  with Electron `42.3.0`; the latest macOS appcast uses the same ASAR release.
- macOS, Linux, and Windows now converge on one selective ASAR extractor and
  one fail-closed semantic patcher. The legacy unified diffs were removed.
- The cross-cutting patch strategy is recorded in
  `docs/adr/2026-08-06-shared-semantic-desktop-patcher.md`, superseding the
  preliminary ADR assessment above.
- The latest shell required new headless Electron shims for power-monitor and
  cookie APIs, plus the new synchronous initial-sidebar bootstrap contract.
- Browser Electron metadata is generated from the extracted package rather
  than a stale hard-coded value. The server already uses the same metadata.
- Windows setup and startup scripts support installed Store discovery,
  explicit ASAR/CLI paths, safe port handling, loopback-by-default binding, and
  explicit Tailnet binding.
- Non-default Tailscale CLI path, tailscaled socket, IPv4, and MagicDNS values
  are supported. UTF-8 status decoding handles Unicode Tailnet hostnames;
  explicit Tailscale mode fails closed instead of falling back to loopback.
- Direct HTTP Tailnet origins receive an RFC 4122 UUID v4 fallback based on
  `crypto.getRandomValues`, because `crypto.randomUUID` is secure-context-only.
- Runtime production dependencies were upgraded until `npm audit --omit=dev`
  reported zero vulnerabilities. Electron remains pinned to upstream `42.3.0`;
  its development-only advisory is not present in production dependencies.

### Verification completed

- `npm ci --ignore-scripts`: passed with 209 packages.
- `./setup-windows.ps1`: passed from dependency install through native rebuild,
  4,772-file extraction, 22 semantic transformations, Vite `8.2.1` build, and
  TypeScript server build.
- `npm run build`: passed through the platform-aware Windows entry point.
- Reapplying the patcher reported every transform as already patched, proving
  idempotence.

- Browser QA passed for meaningful first render, sidebar toggle, 390x844 mobile
  default sidebar state, and `/?prompt=...` composer prefill. Remaining console
  warnings are the expected blocked Statsig flushes and an upstream root-route
  warning.
- Tailnet validation bound specifically to the detected `100.x` address,
  returned HTTP 200, and rendered the full Codex UI through that address without browser errors.
  An invalid custom Tailscale socket failed closed and left no listener.
- `npm pack --dry-run --ignore-scripts --json` included the compiled server and
  patched webview while excluding the original ASAR and Desktop source archive.
- `npm audit --omit=dev`: zero vulnerabilities.
