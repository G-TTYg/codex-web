## Pinned Windows runtime defaults

Agent: Codex
Project root: `D:\Users\g-tty\Documents\ChatGPT\codex-web`

### Intent

Make Windows use a repository-pinned Codex runtime by default, independent
from newer Codex binaries installed on the host while retaining the normal
shared account, configuration, and data directories.

### Baseline and plan

- Started from clean merged `main` commit `f594a80` on branch
  `codex/pin-windows-runtime`.
- The previous setup selected the newest installed `OpenAI.Codex` Appx; the
  launcher selected the highest CLI under the Desktop runtime or `PATH`.
- Centralize version contracts, pin exact Windows defaults, verify downloaded
  artifacts, retain explicit overrides, update durable docs, and exercise the
  complete Windows path.

### Artifact findings

- Official CLI `0.147.0-alpha.1.2` publishes separate npm artifacts for
  Windows x64 and arm64 with SRI SHA-512 metadata.
- The x64 archive was downloaded through the user's temporary local proxy,
  matched npm integrity, extracted successfully, and reported
  `codex-cli 0.147.0-alpha.1.2`.
- The official macOS Desktop zip matched its pinned SHA-256, but its ASAR
  differs behaviorally from the Windows ASAR even at the same ASAR version.
  The semantic patcher correctly failed closed at the initial-route contract.
  Windows therefore pins the exact Store Appx instead of reusing the macOS
  ASAR; the patch assertion was not weakened.
- WinGet's Microsoft Store source exposes this package version as `Unknown`, so
  it cannot reliably download a requested historical Appx version. The default
  therefore requires the manifest's exact Store version to be installed.

### Implementation

- Added `scripts/runtime-versions.json` as the canonical version, URL, and
  Windows integrity manifest.
- Initially added a Windows-only runtime helper for resumable downloads, SRI
  validation, architecture selection, extraction, and exact CLI validation;
  the unified work below replaces it with the shared Node implementation.
- Windows setup now requires Appx `26.730.8199.0` by default and prepares the
  project-local CLI. Windows start uses that CLI unless `-CodexPath` is given.
- Nix and the Unix preparation script read the same manifest values.
- Stable behavior is documented in README/architecture/upgrading guidance;
  the decision is recorded in
  `docs/adr/2026-08-07-pinned-cross-platform-runtime.md`.

## Unified macOS/Linux/Windows managed CLI

### Intent

Extend the Windows pin so ordinary Git/npm workflows on all three operating
systems use the same fixed CLI version and acquisition contract by default.

### Implementation

- Replaced the Windows-only CLI helper with `scripts/managed-runtime.mjs`, which
  selects official macOS, Linux, or Windows x64/arm64 npm artifacts, validates
  SRI, extracts to ignored state, and checks the exact executable version.
- Added `scripts/run-server.mjs` as the npm binary/server launcher. It honors an
  explicit `CODEX_CLI_PATH` and otherwise prepares the managed runtime.
- Unix builds now prepare the managed native CLI automatically. Windows setup
  calls the same manager, while Nix reads the same artifact URLs and hashes and
  supplies its store path through a wrapper.
- Expanded the runtime ADR and durable setup/architecture/upgrade guidance from
  Windows-only to all supported hosts.

## Same-version Windows/macOS ASAR compatibility

### Finding and fix

- Reconfirmed that the official macOS ZIP and Windows Appx both report ASAR
  `26.730.61639` and Electron `42.3.0`, while several `app-initial` minified
  identifiers differ. Version equality is therefore not binary equality.
- The shared patcher previously accepted only the Windows forms for routing,
  sidebar, editor, local-media, Statsig, and home-prompt anchors; it correctly
  failed closed on the pristine macOS source instead of silently producing an
  incomplete build.
- Added `replaceOneOfOnce` so a transformation can accept the two independently
  verified source forms while still requiring exactly one match and recognizing
  exactly one post-patch form. Patch behavior remains shared across all hosts.
- Updated the shared-patcher ADR and upgrade runbook so both official Desktop
  sources are mandatory inputs when same-version bundles differ.

### Verification completed

- The official macOS ZIP downloaded through `http://127.0.0.1:7897` matched the
  pinned SHA-256 exactly and extracted 4,772 required files.
- Pristine Windows Appx and macOS ZIP trees each applied all 22 semantic
  transformations successfully; a second pass on each reported every
  transformation already patched.
- The macOS ZIP preparation path, Vite browser build, and TypeScript server
  build passed on the Windows host. This verifies the platform-neutral source
  pipeline but is not a native macOS/Linux runtime test.
- The final default Windows Appx workflow again passed pinned metadata checks,
  extraction, all 22 transformations, and both builds with the managed CLI.
- Prettier, Node syntax, and `git diff --check` passed; production audit stayed
